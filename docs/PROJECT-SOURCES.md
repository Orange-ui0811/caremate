## 发布前需要落实的内容

1. 确认原始工程允许公开再分发的范围，保存对应链接和许可文件；按适用条款保留声明。
2. 区分基础工程能力与后续实际修改。架构文档说明系统行为；变更记录应描述具体修改。
3. `.env`、密钥、运行数据库、会话、日志和本机备份不进入公开仓库；脱敏问题被允许用于模型处理，不等于已获准公开发布。
4. 评估报告与语料逐项核对来源。不能因为文件在 `data/` 下或已有文档引用，就默认可以公开。
5. 学习图谱包含生成的源码快照和证据文件，需单独检查发布范围，不能只检查 `.py` 源文件。

目前没有为整个工程新增 MIT、Apache 等许可证，也没有声明代码全部为独立原创。以上状态应在核实来源后更新。
