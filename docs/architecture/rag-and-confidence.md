# RAG 与证据评估

知识问答由入库处理、混合检索、证据评分、生成前自检和回答生成组成。各阶段需要分别验证，召回到资料不等于最终答案正确。

## 知识入库

示例知识位于 [data/kb](../../data/kb)。[documents.py](../../app/kb/documents.py) 与 [chunking.py](../../app/kb/chunking.py) 处理标题路径、长正文重叠和表格拆分。[dualwrite.py](../../app/kb/dualwrite.py) 协调 MySQL 与 Milvus 的写入及状态更新。

MySQL 保存原文与元数据，Milvus 提供检索索引。两者不构成跨存储强事务；需要关注部分成功、失败状态与重试。

## 查询与检索

[retrieve_knowledge](../../app/graph/nodes.py#L180) 从当前用户原句发起查询理解，生成标准问句和扩展词，再调用 [search_knowledge](../../app/core/retrieval.py)。当前此入口未直接优先使用 `resolved_query`，依赖上下文的短问句需要单独验证。

检索使用向量与 BM25 补充语义和字面匹配，通过 RRF 融合，再执行重排。服务和模型由配置决定。检索策略是否有效应按不同类型问题比较，不能从某个单例推导全面优势。

## 生成前两道检查

第一道由 [compute_evidence_confidence](../../app/core/confidence.py) 计算启发式证据分数：

| 信号 | 权重 | 处理方式 |
| --- | --- | --- |
| 首条结果精排分数 | 0.5 | 裁剪到 0～1 |
| 有效结果数量 | 0.2 | 分数至少 0.3 的结果，数量按 3 封顶并归一化 |
| 前两条结果分差 | 0.2 | 裁剪到 0～1；单条结果时取其分数 |
| 关键条款词命中 | 0.1 | 检查前三条文本是否命中词表 |

计算依赖传入结果的顺序。分数不是回答正确的概率；固定权重也没有通过训练学习。

分数达到运行阈值后，第二道调用 [check_sufficient](../../app/core/selfcheck.py)，让模型输出证据是否足够及原因。任何一关未通过都会进入兜底；通过后整理编号证据，交给主 Agent。

`confidence_check` 节点记录判断，实际分流由其后条件边完成。失败问题及可获得的召回快照进入待审流程。

## 阈值与评估

[runtime_settings.py](../../app/core/runtime_settings.py) 持久化运行阈值；后续请求读取更新值。降低阈值不会补充缺失知识，也不会跳过语义自检。

[eval_ch04.jsonl](../../tests/data/eval_ch04.jsonl) 提供固定评估问题；[eval_ch04.py](../../scripts/eval_ch04.py) 比较检索策略，[calibrate_confidence.py](../../scripts/calibrate_confidence.py) 扫描证据阈值。

| 指标 | 解释 |
| --- | --- |
| 分组 Recall@K | 所需证据组在前 K 项中的覆盖程度，不等于回答准确率 |
| 分组倒数排名 | 各证据组最早命中名次的倒数，不应与只看首个相关项的 MRR 混用 |
| 证据要点覆盖 | 检索材料包含标准要点的程度 |
| 答案要点覆盖 | 生成答案覆盖要点的程度，需说明裁判及评分方法 |
| 可答通过 / 应拒放行 | 给定阈值下的取舍，需同时报告分母与样本构成 |

阈值校准不运行完整的在线生成链路，不能将其结果直接视为包含语义自检与回答生成的端到端误拒率。阈值选择集与独立测试集应分开。

## 复现与排障

按 [部署说明](../../DEPLOY.md) 完成知识入库、向量化和模型配置后，可使用 `make eval-rag` 与 `make calibrate-confidence` 生成本机报告。运行前检查服务可达性，并记录代码、知识库、模型及数据版本。

拒答排查先看 `fallback_source`、分数、各信号和召回快照，再检查自检输入与异常日志。`self_check` 分支可能反映证据不足或自检调用失败，不能仅凭分支名判定唯一根因。

公开仓库不包含本机历史报告；这里不将旧环境的数值作为当前配置的性能承诺。
