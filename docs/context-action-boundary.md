# 上下文限制与动作入口边界

本次修复覆盖 `/api/actions/create-ticket`、`create-refund`、`resume` 和 `/api/agent`，未修改模型提示词或评测评分。

- 工单、退款和续跑请求必须带 `user_id`；服务端核对会话归属。退款还须通过订单归属检查。
- `source` 策略下，页面直接提交会从当前完整会话原文重建状态并检查有效撤回/限制。记忆仅能阻止写操作，解除限制不会执行操作；仍需用户提交表单或明确确认卡片。
- 每个续跑卡片带真实 LangGraph `interrupt_id`，服务端同时核对调用者、checkpoint 所属用户、待确认中断及参数类型。旧卡片、混用订单选择/工单确认、出现更新用户消息后的旧确认均被拒绝。
- 页面创建工单及工具的 `ticket_type` 仅接受“售后、投诉、咨询”，不能填“退款”绕过专用退款入口。普通人工工单的描述可能涉及退款咨询；它不是自动退款操作，任意描述的完整业务语义分类不在本次修复范围。
- 已有会话的 chat、agent、直接动作和续跑接口复用同一 SQLite 会话 lease；在超时、失败和正常结束时释放，限制核对和执行期间避免另一个 API 请求更新同一会话。续跑在持有锁后再次校验。

身份边界：当前项目的 `user_id` 来自浏览器 localStorage，API 也沿用客户端提交的身份字段。这是已有演示身份契约下的归属检查，不是可信登录认证。生产化时应从服务端认证会话获取身份，不能把本次修复描述为已实现完整身份认证。

并发边界：会话 lease 由同一主机共享的技术 SQLite 协调，有效期为配置的 turn timeout 加 10 秒；不是多机分布式事务或写入幂等机制。内部直接调用 runtime 的程序需自行串行化，公开 API 已接入共享 lease。工单写入成功但响应丢失时，仍需核实结果，不能据此声称可以安全重复提交。

验证记录：

- `tests/test_action_context_boundary.py` 加相关 API、runtime、来源上下文及 Workflow 验证脚本回归，共 **59 项通过**（2026-10-27，11.73 秒）。全部使用合成数据、内存图、临时 SQLite 或 MockTransport；未调用真实模型、客户数据库或业务系统。
- `tests/ui/action_context_boundary.cjs` 使用 headless Edge 和完全本地拦截的 HTTP 响应，通过工单确认、订单选择、工单表单、退款表单四项交互；验证身份、会话及对应中断编号传递，浏览器无页面错误。
- `scripts/verify_context_workflow.py` 已适配新增的 `user_id`、`interrupt_id` 续跑参数。

旧客户端必须同步升级：省略 `user_id` 或续跑 `interrupt_id` 返回 422；失效卡片返回 409。更新后的页面保留正常表单与确认流程，并展示服务端拒绝原因。
