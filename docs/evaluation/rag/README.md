# RAG 四策略评估

实验日期：2026-10-11。历史知识库 52 个片段；300 道固定题，五桶各 60。比较向量召回、BM25、RRF 混合召回、混合召回加重排。结果来自保存的 `rag_eval` 报告，公开汇总见 [results.json](results.json)。

## 测试问题怎样设计

题目围绕示例电商知识的政策、商品型号、口语表达、跨文档条件和知识缺口分桶。各桶检查不同失败来源，既报告总体结果，也分别检查各桶表现。

| 桶 | 数量 | 设计目的 | 保存题集中的例子 |
| --- | ---: | --- | --- |
| A 政策 | 60 | 检查明确规则和适用条件的召回 | A1：退货政策是什么样的 |
| B 型号 | 60 | 检查具体型号、部件和参数，避免混用商品 | B1：MH-LP100 的废砂盒多久倒一次 |
| C 口语 | 60 | 检查用户说法与知识标题不一致的语义匹配 | C1：东西不想要了还能退不 |
| D 库外／应拒 | 60 | 检查当时知识中缺少依据的问题 | D1：你们卖不卖活体宠物，能在这买猫吗 |
| E 跨文档／多证据 | 60 | 一题同时包含地区、金额、权益等条件，需要多组依据 | E1：我在新疆下单 80 块钱，运费怎么算，会员的免运费能不能抵 |

完整题集为 [eval_ch04.jsonl](../../../tests/data/eval_ch04.jsonl)，每题保存 `id`、`bucket`、`query`、`expect_section`、`expect_points`、`should_refuse`；多证据题额外用 `expect_sections_all` 指定全部必需证据组。同组章节别名命中任一即可，不同组需要分别覆盖。

例如 E1 不只要求命中“运费”，还要求同时处理包邮门槛、偏远地区及会员权益限制。A1 的标准要点包含“7 天无理由”和“不影响二次销售”；这让评估能够检查是否遗漏条件。

这是项目内部固定题集，已用于开发与调优。知识更新后，原本的库外题可能变得可答，因此标签必须结合报告当时的知识版本理解，不能将 D 桶长期视为绝对真值。

## 总体结果

A/B/C/E 共 240 道可答题参与下表。D 桶单独观察拒答；不将其混入召回率分母。

| 策略 | 分组证据 Recall@5 | 分组倒数排名 | Top10 证据要点覆盖 | 答案要点覆盖（模型裁判） |
| --- | ---: | ---: | ---: | ---: |
| 向量召回 | 97.3% | 0.833 | 99.7% | 73.5% |
| BM25 | 91.3% | 0.783 | 96.2% | 84.2% |
| 混合召回 | 94.8% | 0.825 | 99.8% | 89.7% |
| 混合召回＋重排 | **98.4%** | **0.893** | 99.4% | **93.7%** |

报告保存值已四舍五入为三位小数，表格沿用该精度。向量单路的召回已经较高；混合但不重排并未超过它。是否保留组件要看对照，不能从流程复杂程度推断效果。

多证据题仍然更难。单段命中、证据要点覆盖、最终答案要点覆盖是三个不同层次；检到了正确章节，也可能遗漏适用条件或没有把材料正确用于回答。

## 指标与实验边界

- **分组 Recall@5：**每题所需证据组在前五项中的覆盖比例，再对 240 题平均。
- **分组倒数排名：**每个必需证据组首次命中的排名倒数，组内、题间平均。这里不是只计算任一相关项首次命中的标准 MRR。
- **证据要点覆盖：**拼接前十条证据后，按标准要点做机械匹配；不等于语义充分。
- **答案要点覆盖：**使用模型裁判评价生成答案是否覆盖标准要点；不能改称人工准确率。
- 当次旧管线的 D 桶拒答记录为 60/60，忠实度检查还保留了一条未通过案例 C54。它们不代表当前版本的端到端误放或幻觉率。

该历史实验的模型配置、知识和拒答路径与后续最高重排分评分不同，也与 [Embedding 实验](../embedding/README.md)的纯向量排序不同。不能将不同实验的最好数字拼成一套当前系统成绩。
