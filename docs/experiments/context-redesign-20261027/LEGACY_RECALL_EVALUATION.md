# 面向客服任务的摘要与原文回查：实验问题重定义

本轮是设计与接入修订，没有启动新一轮付费模型对照。此前hybrid6的46/48及Token不能作为本方案成绩。

## 面试中的主问题

面对对象更正、话题切换和远距离指代，怎样组织近期对话、长期背景和关键原文，在可接受成本下提高多轮客服任务完成率？

项目设计：窗口维持近期交流；滚动摘要保留早期任务背景；BM25回查原问答及下一轮，恢复摘要遗漏的具体对象关系、更正和限制；各节点继续使用现有职责和输入方式。收益是待检验的业务可靠性与效果/成本取舍，不是预设“新增组件一定值得”。

## 实现边界

- 保留生产默认：未摘要消息30条触发，保留8轮，原SUMMARY_PROMPT与异步调度不改。
- 保留原节点截取：coref/intent先走原窗口再取最近6条消息；Agent仍走原3000估算Token窗口；查询改写仍仅接收已有消解后的问题。
- 只增加旧问答附加区：对已摘要用户原话BM25取正分前三，每个命中补下一轮，仅限已摘要历史；携带整轮问答，去重、按时间排列、标注来源。
- 不把所有未摘要消息改成全量输入，不新增模型调用、结构化规划或业务执行规则；Agent原system、当前工具调用配对、证据与任务边界均保留。
- 开关context_legacy_recall_enabled默认false；关闭或无匹配时输入必须与原实现相同。开启只在原历史文字和Agent本轮材料增加附加区，不替换原窗口。

## 主对照的通用名称

|方法|代表什么策略|比较回答什么问题|
|---|---|---|
|完整历史|全部可见原问答，无摘要|相比直接携带全部历史，是否改善效果/成本取舍；不称准确率上限|
|仅滑动窗口|原节点截取，无摘要、无回查|近期信息能解决多少任务，远期依赖在哪里失败|
|滚动摘要＋滑窗|项目原有摘要与节点装配|长期背景能否补充窗口丢失的信息|
|检索原文＋近期窗口|不生成摘要的原文检索策略|检索细节的优势与无关键词指代的缺口|
|滚动摘要＋滑窗＋原文回查|本方案|背景记忆和原文证据能否互补，并以多少成本获得收益|

对外不使用“旧方案”“默认组”“T方案”等需要项目历史的名字。所有方法明确窗口、检索、维护与来源规则；不能只给名称而隐去资源差异。

主表比较整体方法，不声称每一组都是单变量实验。最严格的组件对照是“滚动摘要＋滑窗”与“本方案”：保留所有原处理，仅切换回查开关。检索策略的邻轮扩展可另做有/无邻轮消融，不需要把所有变体塞进面试主表。

## 避免随机摘要和连续回答混淆归因

1. 固定前缀诊断：同一份可见历史、同一份已冻结摘要与水位，打开/关闭旧问答附加区；删除附加区后原输入必须一致。报告回查恢复了哪些证据、下游对象与动作是否正确。共享预处理的实际费用单列，不伪装为各组都真实调用了一遍摘要。
2. 连续任务评测：各方法正常维护摘要，使用各自实际前一轮回答继续追问；成本计入各自真实全部维护及重试。这里允许错误传播，不保证各组后续输入相同，因此用于比较整体表现，不能把每一轮差异都归因于BM25。
3. 核心配对对照重复运行，报告波动和按会话聚合的区间；同一轨迹的三问不能当作三个独立样本。不能挑最好的一次。

## 数据与指标

已见的16条只作开发/回归；另建未用于调参的自建测试集，先定答案与评分再冻结。覆盖短会话、长会话、关键词指代、纯指代、已说明的别称、多对象更正、限制撤回、明确歧义与工具故障；包含无需远期记忆的普通客服问题，避免只测试有利于回查的样本。不称内部自建集为独立外部盲测。

主指标：当前目标对象/动作、实际工具参数、当前业务证据和回答是否正确；信息不足时是否澄清；不擅自执行写操作；整条任务是否完成。记忆证据召回与指代正确率是诊断指标，不能代替端到端任务完成率。

成本：每条轨迹全部模型输入/输出、摘要维护、协议重试；前台/维护分开，给出每类场景的效果与成本。输入缺失是未知费用，不能按0。延迟单列，不从Token同比推导。保留失败原文、来源、工具回执、源码和配置快照。

模型、供应商、思考开关、温度、输出上限、业务工具、知识夹具、提示模板、评分规则保持一致。完整历史超过接口容量时单列超限；不静默截断再称完整历史。共同业务修复对所有方法一致，不能算成本方案独有收益。

## 可检验的设计收益

- 相比仅滑窗：能否恢复窗口外的对象关系和有效更正。
- 相比仅摘要：能否核对摘要遗漏/混淆的关系和限制。
- 相比仅检索：摘要能否帮助无明显关键词的历史指代。
- 相比完整历史：能否降低重复输入，同时保持任务效果在可接受范围。
- 普通短会话是否增加无益输入；可靠性提升是否值得对应Token与延迟代价。

结论可以是收益有限、成本过高或某些场景退步。面试展示应解释设计假设、对照、证据和失败边界，不为展示亮点调整测试或选择性报告。
