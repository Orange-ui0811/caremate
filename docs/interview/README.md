## 一版可核对的项目描述

**客小助 · CareMate｜电商售后客服系统复现与扩展**

面向电商商品咨询与售后场景，采用确定性 Workflow 与单主 Agent 结合的架构，覆盖混合检索问答、九类意图分流、人工确认和知识反馈。技术栈：Python、FastAPI、LangChain、LangGraph、Milvus、MCP、Langfuse、MySQL。

- **RAG 与证据校验：**采用标题分节、句子重叠与表格拆分组织知识，组合 BGE-M3、BM25、RRF 与 BGE-Reranker；项目归档 300 题五桶评估中，240 道可答题 Recall@5 为 98.4%，模型裁判答案覆盖为 93.7%。商品知识分支使用四信号置信度与生成前语义自评；支持管理端阈值持久化及后续请求生效。
- **Workflow 与 Agent：**基于 LangGraph 将九类意图映射到五个处理分支，固定商品咨询检索与退换货/售后的取单、政策获取步骤；使用 LangChain 组织模型消息、结构化输出与工具绑定，通过 MCP 发现模拟业务服务工具，结合参数校验、权限检查、步数限制与人工确认控制执行，并接入 Langfuse 追踪。
- **上下文工程：**组合滑动窗口、滚动摘要与指代消解；24 条、每条 24–64 轮的合成长对话历史对照中，相比仅滑窗，末次追问规则通过率由 25.0% 提至 87.5%；相比完整历史，末次指代改写平均输入 Token 从 11,581 降至 1,247，保留逐条输出、摘要维护开销与离线审计脚本。
- **知识反馈与分类：**将低置信度、生成前自评不足及用户未解决反馈落入 MySQL，保留可获得的召回快照，执行标准化与查重归并，人工核准后写回知识库；建设旁路 RoBERTa 17 类多标签主题分类流程，当前 149 条测试样本 micro-F1 为 93.66%，包含阈值扫描与 ONNX 导出，用于呈现知识缺口分布。

上面描述系统能力与现有证据。投递时再按真实情况补上个人承担的模块、具体改动和复现记录。若版面紧张，优先保留“做法 + 一个关键结果 + 评估范围”，四信号校准的具体误放/误拒数字可留到面试展开。

## 约 90 秒开场

> 我基于一个已有的电商售后客服工程做学习、复现和扩展，重点研究了检索可靠性、业务执行约束、长对话上下文和知识反馈四部分。
>
> 系统先做指代补全和九类意图识别，再进入五个处理分支。商品咨询强制查知识库，退换货和售后先查订单、再取政策；Agent 在这些步骤之后决定是否继续调用工具。涉及创建工单时，需要用户确认。订单、物流和售后接口目前使用模拟业务数据。
>
> 检索采用向量与 BM25 混合召回、RRF 融合和重排。知识分支在生成前再检查证据，证据不充分就拒答。上下文部分保留了完整历史、仅滑窗、摘要加滑窗的对照实验，分别检查实体是否保留、指代是否正确和输入 Token。
>
> 未解决的问题会进入反馈池，经归并和主题分类辅助人工补知识。这个系统目前是单主 Agent，尚未实现多智能体或工业参数自动优化。它和目标岗位的连接点，是把必要步骤、工具执行、证据与评估做成可观察、可验证的流程。接下来我用一个商品问题、一条业务流程和一份评估报告展示这些部分。

不建议开场背完全部指标。先让面试官理解要解决的问题与一条执行链，再按对方追问展开数字。

## 演示准备与失败预案

1. 提前打开六个标签：本页、聊天、RAG 评估、观测、分类器验收、Langfuse。预选一条确实含模型用量的 trace。
2. 当天先跑一次选定问题，核对回答和引用。演示结果受模型与网络波动影响，不把旧截图当作刚运行的结果。
3. 预备明确标注日期的录屏或运行记录。等待时讲执行图；若现场慢或失败，切到“这是预演记录”，再用 trace 定位原因。
4. 不在面试现场重跑 300 题评估、训练、向量全量重建或批量飞轮。展示已保存报告和复算入口即可。
5. 上下文效果使用归档的同题三策略对照；两句短对话只能检查一次指代，不能证明 24–64 轮历史管理效果。
6. 知识审核展示待审字段和核准入口；未核对草稿时取消操作。别为了演示改变现有知识与评估基线。

## 针对 3D 打印 Agent 岗位的收尾

可以迁移的是方法：用固定阶段控制感知/诊断/执行顺序，用带 schema 的工具封装能力，用前置条件、人工确认、失败处理和回归样例约束执行，用 RAG 提供可追溯的排障依据。

当前没有实现传感器融合、图像故障感知、真实打印机参数闭环、标准 Agent Skills 注册体系或生产 Multi-Agent 协作。已有的工具注册表可以作为能力封装基础，离线 Harness 上下文对照也可以作为实验讨论材料，但不能直接改名为岗位要求的完整能力。

一个合适的下一步练习是：选择“喷嘴堵塞”这一种故障，定义输入证据、诊断输出、允许执行的动作、前置条件、失败回退和十条回归案例。面试时把它作为迁移方案提出，尚未实现就明确说是方案。
