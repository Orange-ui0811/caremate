多意图上下文与续办 v2

入口与版本
MULTI_INTENT_CONTEXT_V2_ENABLED 默认为 false。多意图模式的新消息在开启时产生 task_plan_version=2；
单意图入口保持原流程。检查点没有版本或版本为1时按旧语义恢复，恢复不重新调用规划模型。
回退只关闭新计划入口；保持新版执行器处理已经挂起的v2计划，不恢复数据库备份覆盖已提交工单。

正常多任务链路
安全前置 -> 基线历史选择 + 可信订单候选 -> 单次ContextPlan模型调用 -> 来源/归属/冲突校验
-> 输入就绪调度 -> 各业务子流程 -> 同组一次选单/独立写操作确认 -> 用户自然回复。
空任务或没有订单对象的一般知识/其他问题，沿用既有单意图回退路径；这里可能继续发生原有模型调用。
“一次”指上下文理解与多任务规划合并，不是整轮回答只调用一次模型，也不消除模型协议重试。

对象与历史
原话source/reference_span必须能在当前消息找到；派生query不伪装成持久消息原文。
candidate_ref只指向当前用户拥有的服务端候选。摘要/客服历史能辅助理解，不能独自创建订单候选或授权。
明确当前订单优先；明确两笔中的未指明一笔不能按最近一笔猜。独立退款不借用物流订单。
每个任务持有subject_ref、绑定提议、校验原因和task_context，子流程不回捞兄弟任务。
商品说明继承已核验商品名称；通用咨询不绑定订单；订单没有型号时不能补写Pro/MH-LP100。

状态与依赖
WAITING_DEPENDENCY用于等同组订单/商品资料；WAITING_USER用于实际选择或确认。
同组一个任务展示选单，其余依赖等待。选择后重新校验归属并唤醒依赖，取消只影响该组。
商品资料失败记为upstream_order，不当成知识库缺失；证据闸拒答通过evidence_gate单独记录。
DONE任务不重新调度；现有operation_id和SQL回执继续防重；恢复和重启不会重新规划。

独立核查：scripts/audit_context_v2.py；原标签与审计标签分别保存，初始化错误及评分修正都在报告披露。
数据库、检查点和调用池使用隔离目录；Gitee调用真实模型，订单为项目演示数据，工单为隔离SQL数据。
保持生产历史召回开关与运行阈值；不运行原120场景，不重跑基线。

然后追问：刚刚那个订单现在送到哪了，里面是什么商品，有没有使用说明。
应承接1001并把智能猫砂盆传给检索，不应再次选单；现有证据充分性检查仍可能拒绝说明问题。
