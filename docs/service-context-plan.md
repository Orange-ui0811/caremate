# 面向客服的来源约束业务记忆与预算控制

本次为隔离原型与对照评测，未更改线上主图、数据库、模型配置或权限流程。

## 业务约束

项目包含订单/物流只读查询、商品和政策RAG、退款确认流程、人工工单及SSE。上下文首先需要可靠区分当前订单、商品关系、否定/撤回、更正和歧义；历史客服承诺不等于工具验证，用户提到退款不等于确认执行。知识库缺口与召回失败不能靠扩大聊天记忆解决。

## 实现

- 每个ServiceMemory绑定单个会话，输入只能追加；原文不可变，按消息号及字符区间定位证据。
- 完整句中的明确用户更正、当前选择和未选定状态形成候选槽位。假设和问题不变成槽位；客服表述单独标记未验证。不生成操作授权。
- 状态必须与支持原句一起进入上下文。超长消息按句子处理；无标点超长句只保留带不完整标记的片段，遇到可能改变对象的片段将对象转为待澄清。
- 查询相关原句按词项、早期/最新指示和关系词从当前可见历史中选取；受证据预算约束，不读取未来、其他用户会话、标准答案或工具夹具。
- 普通近期原文使用剩余空间；单个超长轮次不会让整个窗口直接为空。整体包包括状态、引用、原文和本轮问题，硬约束为9800估算Token。
- 工具结果原件保存于评测结果，投影保留订单号、运单、状态、关键条款等业务字段与内容哈希。不可裁掉的关键字段放不下则显式阻断，不能截断后冒充完整。
- 完整请求连同系统词和工具schema共享16000估算Token上限。估算不是供应商分词器；请求过大明确记为本地预算阻断，不发送或无限重试。模型输出同为8192，关闭思考。

借鉴QueryMind的业务执行状态、历史经验与原始结果分离；借鉴Harness的预算、来源可追溯、投影后检查；保留当前原文方案的低维护成本。本轮使用确定性证据检查点，不引入新摘要模型。

## 对照设计

三组：C当前摘要+3000窗口；S原8000原文+1800来源状态；N新业务状态+来源回查，整体上下文9800。C/S复用未修改的既有工作流和评分；所有模型输出重新生成。模型、非思考、工具夹具、读写范围、提示词、温度和输出预算相同；N只改变上下文组织和工具投影。同完整输入上限不等于同实际输入量。

16条原有会话固定选择八族variant0/2（24/64轮），另加8条声明用途的压力变体，每条两次因果追问，每组48条，共144条。压力变体保持原任务和答案，增加关键消息长度或历史登记密度，单独报告，不能作为盲测泛化证据。仅传输异常重试一次，保留语义、解析、截断及本地预算失败。

记录任务规则、规划对象、指代、每阶段状态、摘要维护、API用量、P50/P95；保留已知否定引用评分误判。摘要失败/本地输入阻断单列，不能混成模型记忆差异。按会话配对bootstrap只供探索，八族模板相似性限制统计解释。

每个请求、实际尝试和源码/数据快照保存。离线按可见前缀重演，验证参数、源区间、状态和评分。完整历史轮为给定文本，未计入其生成成本。线上SSE、生产RAG、退款提交以及跨进程持久化不在本轮模型实验范围；不能将只读实验通过视为可直接上线写操作。

## 上线前仍需完成

利用现有会话消息ID实现持久化与乐观并发控制；按用户和会话权限回查原文；把业务工具核验状态与用户候选分开；将真实RAG和工具结果纳入完整请求预算；对关键词规则不覆盖的自然语言变体做独立验证。新方案不得绕过既有订单归属、退款确认、知识置信度与转人工判断。
